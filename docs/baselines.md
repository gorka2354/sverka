## Что из этого следует

**1. Пол зависит от баланса классов, и на тесте он ниже 0.667.** При балансе 50/50 константа
«всё галлюцинация» даёт F1 = 0.667 просто потому, что F1 не штрафует за ложноположительные так
же сильно, как за пропуски. Общая формула — `2π/(1+π)`, где π — доля положительных. Из матрицы
ошибок baseline лидерборда (`docs/research.md`, §5.1) следует π_public ≤ 0.448, то есть пол на
публичном наборе **не выше 0.619**. Это же объясняет выбор запасной метки в `predict.py`: при
отказе детектора ставим 1, потому что пропуск стоит дороже ложной тревоги.

**1а. Настоящая планка на этом сэмпле — 0.913, и она почти наверняка артефакт.** Правило
«в ответе есть хотя бы один TOOL_CALL → метка 1» даёт F1 = P = R = 0.913 (tp=21, fp=2, fn=2).
Распределение жёсткое: из 23 ответов без вызовов 21 отрицательный, из 23 ответов с вызовами
21 положительный. Вероятное объяснение — способ, которым нарезался сэмпл: позитивы брались из
ходов-действий, негативы добирались из текстовых ходов.

**Практическое правило, обязательное для всех последующих замеров:** метрики считать
**отдельно по стратам** «ответ с вызовом» (n = 23) и «ответ без вызова» (n = 23). Ни одна
гипотеза не принимается по общей цифре, пока сабмит #2 не покажет, переносится ли артефакт
на тестовый набор.

**2. Артефакта длины нет — но проверка нашла не тот артефакт.** Детектор «длинный ответ =
галлюцинация» дал 0.348, ниже константы и на уровне случайного. По длине переобучиться не на
чем: медиана ответа без вызова 465 (label=0) против 610 (label=1), с вызовом 434 против 302 —
знак корреляции меняется между стратами. Проверка была правильной по замыслу и слишком узкой
по охвату: искали корреляцию с длиной, а в данных сидела корреляция со структурой ответа (§1а).
Урок на будущее — контрольные признаки перебирать списком, а не по одному.

**3. Главное: ширина интервала 0.253.**

Это количественное доказательство тезиса из `strategy.md`, §4. На 46 примерах доверительный
интервал F1 составляет четверть шкалы — то есть **отличить решение с F1 = 0.70 от решения с
F1 = 0.85 на этих данных невозможно.** Любое сравнение двух вариантов здесь будет сравнением
шума.

Практический вывод, определяющий порядок работ: **собственный корпус (inc-2) важнее качества
судьи (inc-3)**. Пока валидация не сузит интервал, улучшения нечем измерять, а сабмитов
всего десять и обратная связь по ним частичная.

**4. Разброс по доменам заметен даже на константе:** от 0.625 на retail до 0.706 на
banking_knowledge — просто из-за разного баланса классов в маленьких подвыборках (по 11–12
примеров). Смотреть на доменную разбивку как на сигнал качества на таких размерах нельзя;
она нужна только для контроля, что решение нигде не разваливается полностью.

## Замер по стратам — 28.08.2026

Воспроизводится `python scripts/evaluate.py --detector all`. Общая метрика на этих 46
примерах непригодна для сравнения вариантов, потому что в основном меряет наличие вызова
инструмента. Сравнивать надо внутри страт.

| Детектор | страта «с вызовом» (n=23, доля позитива 0.91) | страта «без вызова» (n=23, доля позитива 0.09) |
|---|---|---|
| всё = 1 | F1=0.955 P=0.913 R=1.000 | F1=0.160 P=0.087 R=1.000 |
| есть TOOL_CALL ⚠️ | F1=0.955 P=0.913 R=1.000 | F1=0.000 (по построению) |
| номер хода ≥ 5 ⚠️ | F1=0.905 P=0.905 R=0.905 | F1=0.250 P=0.143 R=1.000 |
| гейты `OR` | tp=11 fp=0 | не срабатывают по построению |

Что отсюда видно и чего не видно из общей таблицы:

**Страта «с вызовом» почти вырождена.** Доля позитива 0.91, поэтому константа «всё = 1»
даёт там F1 = 0.955, и превзойти её можно только идеальной точностью. Все наши гейты живут
именно здесь и физически не могут ошибиться: отрицательных всего два, и оба недостижимы.

**Вся содержательная работа — в страте «без вызова».** Там доля позитива 0.09, константа
даёт F1 = 0.160, и это единственное место, где судья способен показать себя. Оба примера
этой страты с меткой 1 — ложный отказ и ложный запрос уже известных данных, то есть ровно
тот класс, под который нет ни детерминированной проверки, ни опубликованного метода.

**Практический вывод для inc-3:** судью надо мерить на страте «без вызова», а не на общей
метрике, иначе его вклад утонет в артефакте.

### Разделяющий замер: решённые против проваленных — 28.08.2026

Доля срабатываний на решённых задачах сама по себе не говорит, есть ли у гейта сигнал:
гейт, который не срабатывает никогда, покажет там идеальный ноль. Поэтому та же проверка
прогнана на симуляциях с `reward == 0.0`. Если гейт ловит настоящие дефекты, на проваленных
задачах он обязан срабатывать заметно чаще.

| Гейт | решённые (n=1318) | проваленные (n=481) | обогащение |
|---|---|---|---|
| A — недоступный инструмент | 0.53% | **1.66%** | **×3.1** |
| B — повтор провалившегося вызова | 0.08% | 0.21% | ×2.6 |
| M — два и более мутирующих вызова | 0.83% | 0.62% | **×0.7, то есть нет** |
| D — нарушение схемы аргументов | 0.00% | 0.00% | не срабатывает вовсе |
| любой | 1.44% | 2.49% | ×1.7 |

Три вывода, и два из них неприятные.

**Гейт A — единственный с ясным сигналом.** Втрое чаще на провалах, и содержательно это
всегда одно и то же: агент telecom вызывает `check_network_status` или `run_speed_test`,
которые по политике выполняет пользователь на своём устройстве.

**У гейта M обогащения нет — оно даже отрицательное.** Это независимое подтверждение того,
что уже было видно по объяснениям: многовызов коррелирует со сложностью хода, а не
с ошибкой. Признак остаётся входом для судьи и точно не получает права метки.

**«Ноль ложных» у схемного гейта ничего не измеряет.** Он не срабатывает ни на решённых,
ни на проваленных: в τ²-bench вызовы проходят через харнесс, который сам валидирует
аргументы, поэтому нарушений схемы там просто нет. Это ровно та же ловушка, что и с
достижимыми отрицательными на выданном сэмпле — величина не определена, а не хороша.
Померить схемный гейт можно будет только на данных, где вызовы не отфильтрованы харнессом.

Отдельно закрыт пробел по banking: 132 хода из решённых задач трёх сабмитов,
**ноль срабатываний**. Домен в аудит раньше не попадал, потому что его файлы по 250 МБ.

## Стоковый ревьюер tau2-bench как бейзлайн — 28.08.2026

Прогон `review_llm_judge.py` из tau2-bench на `qwen3.5:9b`, режим чёрного ящика: поля
с приватной истиной задачи (User Instructions, Example Action Trajectory, NL Assertions)
заполнены заглушкой. Годных строк 33 из 46 — двенадцать ответов не дали валидного JSON,
все на окнах 16384 и больше, ещё одна исключена как обрезанная по контексту.

| Что меряем | F1 | P | R |
|---|---|---|---|
| ошибка **именно на проверяемом ходу** | 0.435 | 0.833 | 0.294 |
| **хоть какая-то** ошибка агента | **0.765** | 0.765 | 0.765 |

**Детекция 0.765 выше и тривиального пола 0.667, и наших гейтов 0.647** — это первое
измеренное свидетельство, что рубрика организаторов несёт настоящий сигнал.

Разрыв между строками объясняется полностью: **8 из 12 пропусков — это находки, приписанные
другому ходу**. Модель ошибку видит, но не привязывает её к нужному месту. Для нашей задачи
локализация не нужна: контекст обрывается ровно перед проверяемым ходом.

Контроль интерпретируемости: на семи строках, где детерминированный гейт уже дал ответ,
ревьюер нашёл ошибку в четырёх (recall 0.57 на заведомо разрешимых). Узкое место — модель,
а не рубрика.

⚠️ Цифра 0.765 смещена в оптимистичную сторону: исключены самые длинные примеры, то есть
сильнее всего недосчитан banking с крупнейшими контекстами.

## Как воспроизвести

```bash
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -e ".[dev]"
./.venv/Scripts/python.exe scripts/evaluate.py --detector all
```

Строки с гейтами и артефактами воспроизводятся `scripts/probe_signals.py` (добавляется в inc-1).

Отдельный venv нужен: в глобальном Python на машине стоит web3 со сломанным pytest-плагином,
из-за которого падает сбор тестов.
